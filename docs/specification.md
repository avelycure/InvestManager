# Спецификация плагина Invest Manager для Obsidian

Статус: проектная спецификация с согласованными требованиями и явно отмеченными вариантами, которые ещё нужно выбрать. Плагин предназначен только для Obsidian на компьютере. Он помогает быстро проверить новости и показатели по выбранным компаниям и темам. Пользователь задаёт интересы файлами в своём хранилище Obsidian, а результаты сохраняются в ежедневных заметках папки статистики. Агент открывается отдельной вкладкой в основной рабочей области Obsidian с кнопками запуска и свежим отчётом.

## 1. Пользовательский сценарий

1. В настройках пользователь выбирает четыре Markdown-файла Obsidian: компании в портфеле, интересующие темы, публичные Telegram-каналы и новостные издания. Кнопка **Инициализировать** может создать их начальные шаблоны в `Статистика`. Отчёты пишутся в эту же фиксированную папку.
2. Пользователь задаёт время утренней сводки по Москве, по умолчанию 09:00. За 30 минут до него плагин начинает подготовку. В заданное время закрывает окно публикаций, проверяет появившиеся во время подготовки материалы и завершает обработку. Результат может быть готов позже. Пользователь также может запустить сводку командой в любое время.
3. Плагин создаёт или дополняет заметку текущего дня в папке статистики. Во вкладке агента появляются короткий статус, только что созданный отчёт целиком и ссылка на дневную заметку.

Вкладка агента показывает последний созданный раздел отчёта тем же наглядным Markdown, что и ежедневная заметка. Отчёт можно прочитать за 5–10 минут или быстрее, если значимых событий мало.

Интерфейс агента — отдельный тип вкладки Obsidian в центральной рабочей области, визуально похожий на страницу. Вверху расположены кнопка создания сводки, состояние последнего запуска и кнопка открытия дневной заметки. Ниже показан только последний сформированный отчёт с разделами:

1. **«Новости в мире на сегодня»** — значимые события по темам из пользовательского файла, найденные в выбранных изданиях и Telegram-каналах.
2. **«Компании в портфеле»** — один блок на каждую компанию из файла портфеля: график акции, капитализация выпуска из ISS Мосбиржи, до пяти датированных публикаций пресс-центра и трёх материалов СМИ или Telegram. Этот файл содержит только компании, которыми пользователь владеет.
3. Остальные разделы добавляются позже без изменения принципа работы существующих разделов.

Название «на сегодня» служит подписью в интерфейсе: точный интервал публикаций остаётся последними 24 часами по правилам раздела 4 и явно показан рядом с временем обновления. Одно событие, относящееся и к общей теме, и к компании, может отображаться в обоих разделах с одной ссылкой на источник; в полной сводке оно не раздувает объём повтором. Если по разделу ничего значимого не найдено или его источники недоступны, это видно прямо в разделе. Команда Obsidian открывает существующую вкладку агента или создаёт её, если она ещё не открыта. Это интерфейс плагина, а не редактируемый Markdown-файл; входные конфигурации и ежедневные отчёты остаются обычными заметками. Боковая панель для агента не требуется. [Документация Obsidian о пользовательских вкладках](https://docs.obsidian.md/Plugins/Getting%20started/Use%20React%20in%20your%20plugin).

## 2. Настройки и входные данные

| Настройка | Назначение |
| --- | --- |
| Файл компаний | Только компании портфеля; по их тикерам строятся графики и запрашивается капитализация, а также собираются новости. |
| Файл тем | Список тем для общей новостной сводки. |
| Файл Telegram-каналов | Явный список публичных каналов для проверки. Плагин не должен обходить все подписки аккаунта. |
| Файл новостных изданий | Список выбранных пользователем крупных российских и международных изданий. |
| Папка статистики | Фиксированный корень `Статистика` для ежедневных заметок с результатами. Плагин не может выбрать другую папку для записи. |
| Время и часовой пояс | Настраиваемое время по Москве, `Europe/Moscow`, по умолчанию 09:00; подготовка начинается за 30 минут. |
| Режим LLM | Выбор локального сервера или облачного API, совместимого с Chat Completions; адрес API, идентификатор модели и проверка подключения. Для облачного режима ключ выбирается из хранилища секретов Obsidian. |
| Доступ к Telegram | Доступны MTProto от имени аккаунта и публичный веб-просмотр. Для MTProto нужны собственные `api_id` и `api_hash`, вход с кодом и защищённая сессия в секретах Obsidian. |
| Источники данных | Для каждого типа данных выбран предзаполненный источник. В настройках его можно заменить на другой поддерживаемый источник, отключить или вернуть значение по умолчанию. Для платного API пользователь вводит собственный ключ. |

Плагин проверяет существование и доступность указанных файлов и папки, показывает понятную ошибку при неверном пути или записи. Файлы остаются обычными Markdown-заметками и редактируются пользователем. Предлагаемый минимальный формат:

| Файл | Поля одной записи |
| --- | --- |
| Компании | Обязательно: название и тикер на Московской бирже. Столбец «Инвесторам» сохранён для будущего раздела МСФО и пока не используется. Отдельный столбец «Пресс центр компании» содержит адрес страницы корпоративных новостей или её RSS/Atom-ленты. Пустой столбец не мешает чтению новостей из изданий и Telegram. |
| Темы | Название темы; при необходимости позже добавляются уточняющие слова. |
| Telegram-каналы | Название и публичный `@username` либо ссылка `https://t.me/username`. Числовой Telegram ID не требуется. |
| Новостные издания | Название и прямой адрес RSS/Atom-ленты. Плагин использует только указанные источники для общей сети новостей, если пользователь не расширит список. |

Для четырёх входных файлов принят формат Markdown-таблиц и списков согласно образцам. Столбцы, обязательность полей, примеры и правила ошибок закреплены в [описании входных файлов](config-formats.md). Плагин не должен зависеть от расположения файлов в определённой папке.

### Источники: значения по умолчанию и замена

Списки **что отслеживать** остаются в Markdown-файлах: компании, темы, издания и Telegram-каналы. Настройка **откуда получать данные** задаётся отдельно по типу данных. Например, замена поставщика Telegram не изменяет файл каналов; замена источника золота не изменяет список компаний.

При выборе облачной модели независимые RSS-ленты, Telegram-каналы и источники рыночных данных запрашиваются параллельно с ограничением числа одновременных запросов. Отчёты по разным компаниям тоже обрабатываются параллельно. При выборе локальной модели эти операции выполняются последовательно, чтобы не перегружать локальный сервер. Лента каждого издания загружается один раз, затем её публикации сопоставляются со всеми заданными темами и компаниями.

| Тип данных | Предзаполненный источник | Что можно изменить |
| --- | --- | --- |
| Новости изданий | Издания и адреса лент из пользовательского Markdown-файла; предустановленного списка редакций нет. | Состав и адреса в файле, а также поддерживаемый способ чтения ленты для каждого источника. |
| Публичные Telegram-каналы | Публичные страницы Telegram до подключения аккаунта; охват может быть неполным и это явно отмечается в отчёте. | MTProto с собственными API ID/Hash и входом в аккаунт либо отключение; список каналов остаётся в Markdown-файле. |
| Графики и капитализация компаний | Открытый ISS Мосбиржи по тикерам из файла компаний. | Тикеры в файле портфеля. |
| Brent | Фьючерс BR Московской биржи с указанным контрактом и датой сделки. | Дневной спот EIA с датой наблюдения и собственным ключом API либо отключение. |
| USD/RUB и CNY/RUB | Официальные курсы Банка России. | Источник каждой валютной пары отдельно; тип курса и время данных указываются в отчёте. |
| Золото | GLDRUB_TOM Московской биржи, ₽/г. | Другой поддерживаемый инструмент или источник с явной единицей измерения. |
| Индекс Мосбиржи IMOEX | Дневные значения закрытия из ISS Московской биржи за последние 30 календарных дней. | Можно отключить; другой поставщик появится после добавления адаптера. |
| Ставки и заседания | Официальные страницы Банка России и ФРС США. | Источник ставки и календаря для каждого регулятора отдельно, если реализован подходящий адаптер. |

В интерфейсе рядом с выбором показываются поставщик, единица измерения, частота обновления, условия доступа и требуемый ключ. Кнопка проверки подтверждает доступность выбранного источника и показывает дату последнего полученного значения. Выбор нового поставщика не означает, что плагин умеет читать произвольную веб-страницу или API: для формата нужен поддерживаемый адаптер. После замены подпись показателя и единица измерения в заметке должны отражать фактический источник; спот и фьючерс не смешиваются. При ошибке выбранного источника плагин сообщает об этом, а не переключается незаметно на другой. Секретные ключи не записываются в Markdown-файлы и отчёты.

## 3. Папка статистики и сохранение результатов

Для отчётов используется только структура `Статистика/<год>/<месяц словом>/<число и месяц>.md`, например `Статистика/2026/октябрь/17 октября.md`. Один день соответствует одной заметке. При записи в день, для которого уже есть заметка в прежнем числовом формате, плагин переносит её в новую структуру и дополняет. По явному нажатию **Инициализировать** плагин также создаёт четыре недостающих входных файла в корне `Статистика` и переключает на них пути в настройках; существующие файлы не изменяет. Во всех остальных случаях входные Markdown-файлы только читаются. LLM не имеет файловых инструментов. Пути записи не настраиваются, а символические ссылки на них запрещены. Снимок последней сводки сохраняется в `Статистика/.invest-manager/last-digest.json`; данные прежних версий переносятся туда при загрузке. Внутренний файл настроек самого плагина Obsidian хранит в `.obsidian/plugins/invest-manager/data.json`.

Во вкладке агента пользователь может оценить каждую новость как **Полезно**, **Не по теме** или **Неинтересно**, а отдельной иконкой — **Пометить прочитанным**. Оценки и отметки хранятся в `Статистика/.invest-manager/news-feedback.json`. Прочитанная публикация исключается из следующих отчётов независимо от рубрики, при этом оценка сохраняется. Отметка **Не по теме** исключает публикацию из выбранной рубрики в следующих отчётах; **Неинтересно** исключает её целиком. Последние оценки служат примерами для модели при проверке тем и ранжировании, без обучения или изменения весов модели. При настроенной модели каждая тематическая публикация, в том числе с точным ключевым словом, должна пройти смысловую проверку. Если модель недоступна, отчёт не выдаёт ключевые слова за смысловую проверку и сообщает об ограничении.

Первый запуск за день создаёт заметку. Каждый следующий запуск **добавляет новый раздел со временем формирования**, не стирая предыдущие результаты. Каждый раздел содержит результат автоматической или ручной сводки. Если файл уже существует, плагин сохраняет его содержимое и дописывает новый раздел. Все ссылки из вкладки агента ведут в соответствующую ежедневную заметку.

В ежедневной сводке у каждой компании свой блок с новостями, графиком цены и переключением дня, недели, двух недель, месяца и года; общей таблицы компаний нет. Открытый ISS Мосбиржи даёт капитализацию выпуска по указанному тикеру, которая может отличаться от капитализации всей компании. Раздел МСФО временно отключён. Отдельный отчёт и команда показателей удалены; прежний файл показателей не читается и сохраняется без изменений.

## 4. Расписание и период новостей

- Если Obsidian работает, за 30 минут до выбранного времени по Москве плагин начинает загрузку и предварительную обработку материалов. Эта работа может включать вызовы локальной LLM.
- В выбранное время плагин закрывает окно публикаций и дочитывает материалы, опубликованные после предварительного сбора. Итоговая обработка и запись заметки выполняются после этого; готовность ровно к выбранному времени не гарантируется.
- Если Obsidian открылся во время получасовой подготовки, она начинается сразу. Если в выбранное время ноутбук спал либо Obsidian был закрыт, плагин проверяет пропущенный запуск после пробуждения или открытия Obsidian и выполняет его один раз.
- Ручная команда доступна независимо от расписания и может добавлять дополнительные сводки в тот же день.
- Утренняя сводка охватывает **24 часа до выбранного времени текущего дня** по Москве, даже если запись завершилась позже. Ручная и запущенная после сна сводки охватывают последние 24 часа относительно фактического времени их запуска. Дата последней сводки не меняет этот интервал. Пропущенные дни отдельно не восстанавливаются.
- В сводку попадают материалы по времени их публикации. Публикации старше 24 часов не включаются, даже если компьютер долго не использовался.
- Плагин хранит факт успешного автоматического запуска за день, чтобы не создавать повторную утреннюю сводку при повторном открытии Obsidian.

Для утренней сводки материалы, предварительно загруженные за 30 минут до выбранного времени, не считаются окончательным набором: в заданное время нужно проверить дельту до границы окна. Дата публикации, а не дата загрузки, определяет включение материала. Для ручного и запущенного после сна режима границы фиксируются в момент фактического запуска. Одновременные запуски не должны портить дневную заметку или создавать одинаковые разделы.

## 4.1. Работа с LLM

Плагин поддерживает локальную модель через сервер с API, совместимым с OpenAI Chat Completions, на адресе `localhost` или `127.0.0.1`. Примеры: [Ollama](https://docs.ollama.com/api/introduction) и [LM Studio](https://lmstudio.ai/docs/developer/openai-compat). В облачном режиме пользователь указывает базовый HTTPS-адрес API, совместимого с Chat Completions, и идентификатор модели. По умолчанию указан адрес OpenAI и тестовая модель `gpt-5.4-mini`; другой совместимый провайдер настраивается без изменения кода. Ключ выбирается через локальное хранилище секретов Obsidian и не записывается в файл настроек плагина. Кнопка проверки отправляет короткий запрос выбранной модели. В облачном режиме отобранные тексты новостей передаются выбранному провайдеру. Провайдеры с несовместимым протоколом требуют отдельного адаптера. Автоматического переключения между режимами нет.

Локальная LLM помогает выделять события, убирать повторы и писать короткую сводку, но факты, числа, даты и ссылки берутся из проверенных источников. Из-за различий в скорости компьютеров и моделей время завершения после выбранного времени не фиксируется. При недоступности модели плагин показывает понятную ошибку и сохраняет доступные собранные данные для повторной попытки; правила частичного выпуска сводки уточняются при реализации.

## 5. Сбор и отбор новостей

Сводка объединяет новости выбранных пользователем российских и международных изданий по компаниям и темам, публикации указанных Telegram-каналов и корпоративные новости из столбца «Пресс центр компании» (принимается также написание «Пресс-центр компании»). Плагин читает прямую RSS/Atom-ленту, обнаруженную на странице ленту или типовые карточки новостей с датой на самой странице. Публикации без проверяемой даты не попадают в 24-часовую сводку; неполный охват помечается. Если указан только день публикации без времени, в заметке показывается только день. Корпоративная публикация относится к компании из той же строки файла, даже если название компании не повторяется в заголовке. Несколько публикаций об одном событии объединяются в один пункт. Плагин показывает первоисточник или доступные ссылки на материалы, дату публикации и краткое объяснение связи события с выбранной компанией или темой. Столбец «Инвесторам» сохранён для возможного возврата МСФО и сейчас не используется.

Раздел каждой компании объединяет до пяти последних датированных публикаций её пресс-центра и трёх материалов других источников. Сначала используются публикации за 24 часа; свободные места заполняются более ранними доступными материалами, помеченными 🕘 и показанными с фактической датой. Более ранние материалы ограничены шестью календарными месяцами от конца отчётного периода. Для темы без свежего события — до пяти более ранних публикаций на каждую тему. В тематических разделах сначала выбирается не более трёх новостей одного издания; если других подходящих источников не хватает, оставшиеся места можно заполнить публикациями того же издания. Правило действует и для более ранних тематических новостей. Отсутствующие материалы не заменяются вымышленными новостями. Короткая глубина RSS и неполнота публичного просмотра Telegram суммируются в ограничениях охвата, а реальные сбои источников перечисляются отдельно.

Приоритет получают действительно значимые события: отчётность, дивиденды и корпоративные решения, существенные изменения показателей, решения регуляторов и события по выбранным темам. Публикация с несколькими независимыми подтверждениями обычно важнее единичного неподтверждённого сообщения канала; исходное сообщение всё равно можно показать с явной пометкой. Отсутствие значимых новостей показывается прямо. Плагин не должен придумывать события, показатели или выводы, которых нет в источниках. Формулировка «ничего не пропустил» означает обзор найденного в подключённых источниках за последние 24 часа, а не обещание полного охвата интернета. В конце сводки указывается, какие источники не удалось проверить.

Для Telegram нужны посты только из списка публичных каналов. Вход и чтение истории через MTProto реализованы; плагин не обходит все подписки аккаунта и не читает приватные каналы без отдельного изменения требований. Варианты:

| Вариант | Возможности и ограничения |
| --- | --- |
| Публичная веб-страница Telegram | Посты публичного канала доступны без входа через `t.me/s/username`. Это разбор HTML без документированного API истории: структура страницы и полнота выдачи не гарантированы. Неполный охват помечается в отчёте. |
| Telegram API от имени пользователя (MTProto) | `messages.getHistory` позволяет читать историю от имени авторизованного аккаунта и обойти последние 24 часа. Нужны собственные `api_id`, `api_hash`, вход пользователя с кодом и при необходимости 2FA, а также безопасное локальное хранение сессии. Сессия имеет полномочия аккаунта, поэтому приложение должно ограничить свои действия чтением каналов из файла. Для TypeScript-плагина кандидат — teleproto, поддерживаемый форк GramJS; Telethon потребовал бы отдельный процесс Python. |
| Telegram Bot API | Токен собственного бота позволяет получать новые посты каналов, доступных боту. Бот не может читать произвольную историю по `@username`; ожидающие обновления хранятся не дольше 24 часов. Для чужих каналов, куда пользователь не может добавить бота, этот вариант задачу не решает. |

Данные MTProto-сессии хранятся в секретах Obsidian, не попадают в Git, Markdown-заметки, логи и сообщения об ошибках. Пользователь хочет анализировать посты для личной сводки, не обучая на них модель. Это отличается от обучения, но [условия Telegram API](https://core.telegram.org/api/terms) и [условия использования данных для AI](https://telegram.org/tos/content-licensing) также упоминают применение AI; допустимость личного анализа готовой моделью из текста правил однозначно не следует. По умолчанию тексты и заголовки постов Telegram не отправляются модели: в отчёт попадают отобранные по правилам короткие фрагменты и ссылки. Отдельный выключенный по умолчанию переключатель разрешает пользователю обработку постов локальной или облачной моделью. Технический MTProto-адаптер реализован, однако полноценный показ [официальных спонсорских сообщений](https://core.telegram.org/api/sponsored-messages) пока отсутствует; это ограничение необходимо устранить до публичного распространения MTProto-режима. [Telegram API: история](https://core.telegram.org/method/messages.getHistory), [teleproto: авторизация и сессии](https://docs.teleproto.dev/).

## 6. Рыночный блок

Каждая новостная сводка начинается с компактного блока текущих ориентиров:

| Показатель | Отображение |
| --- | --- |
| Нефть Brent | Доллары США за баррель с точным обозначением: спот или фьючерс и срок контракта. |
| Индекс Мосбиржи IMOEX | Последнее дневное значение закрытия в пунктах и встроенный график с переключением: день, неделя, две недели, месяц, год; даты, ценовая шкала и изменение за показанный период. |
| Доллар США | USD/RUB; по умолчанию официальный курс Банка России. |
| Китайский юань | CNY/RUB; по умолчанию официальный курс Банка России. |
| Золото | По умолчанию цена GLDRUB_TOM Московской биржи, рубли за грамм. |
| Ставка Банка России | Проценты годовых. |
| Ставка ФРС США | Целевой диапазон в процентах годовых. |

Рядом с каждой ценой или курсом должна быть доступна дата и время данных и ссылка на источник. Данные разной частоты не обозначаются как одновременные. При отсутствии свежего значения показывается «нет данных»; старая или среднемесячная цена не выдаётся за текущую. График IMOEX отображается интерактивно внутри заметки: месячный снимок сохраняется в отчёте, для других периодов доступны свечи ISS Мосбиржи. Если история индекса недоступна, график не строится и проблема попадает в ограничения охвата.

Urals исключён из обязательного рыночного блока: доступный и надёжный ежедневный источник с подходящими условиями использования пока не подтверждён. Плагин не подменяет Urals другой ценой или среднемесячной оценкой.

Предзаполненные источники и варианты замены:

| Показатель | Доступные варианты и рекомендация |
| --- | --- |
| Brent | [Мосбиржа](https://www.moex.com/ru/derivatives/commodity/oil/) торгует фьючерсом BR в USD/барр.; через [ISS](https://www.moex.com/a2920) часть данных доступна с задержкой. Это **фьючерс**, а не спотовая цена. Он выбран по умолчанию и показывается с явной меткой контракта. Альтернатива — дневной [спот EIA](https://www.eia.gov/dnav/pet/hist/RBRTED.htm) с датой наблюдения; он может публиковаться позже утренней сводки и требует ключ API. |
| Золото | [Мосбиржа](https://www.moex.com/PreciousMetals), инструмент GLDRUB_TOM в рублях за грамм. Показывать время последней доступной сделки или котировки и статус её актуальности. |
| USD/RUB и CNY/RUB | [Официальные курсы Банка России](https://www.cbr.ru/currency_base/daily/) — понятная ежедневная опорная точка для утренней сводки. Их следует подписывать как официальные курсы, а не биржевые котировки в реальном времени. |
| IMOEX | [История индекса в ISS Московской биржи](https://iss.moex.com/iss/history/engines/stock/markets/index/securities/IMOEX.json) — дневные закрытия с датой каждого торгового дня. Текущий день появляется после публикации итогов; до этого график заканчивается последней доступной датой. |

## 7. Ближайшие заседания по ставке

Рядом с текущими ставками показываются ближайшие заседания Банка России по ключевой ставке и FOMC ФРС США: дата или диапазон дат, число дней до заседания и ссылка на источник. По умолчанию даты обновляются по [календарю Банка России](https://www.cbr.ru/dkp/cal_mp/) и [календарю FOMC](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm); источники ставок и календарей можно изменить в настройках. Если календарь недоступен или дата не подтверждена, это обозначается явно. После заседания блок переходит к следующей дате.

## 8. Вид ежедневной заметки и ответы во вкладке агента

Заметка должна читаться быстро на компьютере. Рыночные данные и новости компаний показываются компактными таблицами; новости мира — короткими пунктами. Заголовки, умеренные эмодзи, жирное выделение и сворачиваемый блок ограничений помогают находить нужное без длинного полотна. В заметке есть **«Главное»**. Новости мира и портфеля имеют собственные заголовки. Порядок:

1. Время формирования и точный 24-часовой интервал.
2. «Главное»: компактный рыночный блок, ставки и даты заседаний. Далее идут «Новости по компаниям в портфеле» с одной таблицей на компанию и «Новости в мире на сегодня».
3. «Новости в мире на сегодня»: публикации сгруппированы по темам; название каждой темы показано один раз подзаголовком. У каждой публикации только заголовок, дата и ссылка на источник.
4. Число проблем видно сразу; полный список недоступных источников и ограничений охвата раскрывается по запросу.

Целевое время чтения подробного уровня — **5–10 минут**. Это не минимальный объём: при малом количестве важных событий плагин пишет короче и не добавляет текст ради длины. Рыночные цифры и даты заседаний идут отдельными строками таблицы. Даты текущего года показываются как «17 октября», с годом только для другого года. Модель выбирает значимые события и переводит заголовки иностранных публикаций на русский язык, когда настроена. Пункты не содержат отдельных строк «Тема» или «Суть». Повтор одного события из Telegram и СМИ не занимает два пункта. Полные материалы доступны по ссылкам.

Пример структуры без вымышленных котировок и новостей:

```text
Сводка · период: 15 октября, 09:00 — 16 октября, 09:00 МСК · готова: [время]

Главное
| Показатель | Значение | На дату | Источник |
| Brent | … $/барр. | … | … |
| USD/RUB | … ₽ | … | … |
| Золото | … ₽/г | … | … |

Компании в портфеле
#### Компания
График акции · капитализация выпуска
| Дата | Публикация | Источник |
| 🕘 14 октября | [Заголовок] | Пресс-центр компании |
| 16 октября | [Заголовок] | Издание |
Новости в мире на сегодня
#### Инфляция
- [Заголовок новости] · [дата] · [источник]

Источники: [проверено] · [недоступно]
```

Область действий вкладки показывает сообщения «Сводка готова — открыть заметку» либо короткое описание ошибки и действия для её исправления. Ниже отображается только последний сформированный отчёт. По завершении автоматического или ручного формирования плагин обновляет его и отправляет локальное уведомление о готовности со ссылкой на дневную заметку. При частичном результате уведомление обозначает неполный охват.

## 9. Ошибки и достоверность

- Ошибка одного источника не отменяет готовую часть сводки. В заметке и статусе виден неполный охват.
- Если входной файл отсутствует, пуст или содержит непонятные записи, плагин называет файл и проблему, не подставляя догадки.
- Если цена или ставка недоступна, отображается отсутствие данных и время последней успешной проверки, без маскировки устаревшего числа как текущего.
- Если пользовательский источник недоступен, плагин не использует другой без явной настройки и помечает соответствующий раздел как неполный.
- Публикации без проверяемой даты не используются как события последних 24 часов без отдельного правила для таких источников.
- Генерация не должна менять исходные файлы компаний, тем и каналов.

## 10. Пошаговая реализация

1. Десктопные настройки четырёх Markdown-файлов и папки статистики, центральная вкладка агента, чтение входных файлов, команды и создание ежедневной заметки с добавлением новых разделов.
2. Получение постов указанных публичных Telegram-каналов и краткая ручная сводка за 24 часа с источниками.
3. Подключение новостных источников по компаниям и темам, отбор и объединение повторов.
4. Рыночный блок и календари заседаний из предзаполненных источников с настройкой замены для каждого типа данных.
5. Локальный режим LLM, предварительный сбор за 30 минут до выбранного времени, точная граница публикаций в заданное время и восполнение пропущенного запуска после сна или открытия Obsidian.
6. Графики и капитализация компаний внутри ежедневной сводки без отдельной команды показателей.

Этапы 2–6 не входят в текущий технический каркас репозитория. Каждый этап проверяется на реальных входных файлах и примерах сводок до перехода к следующему.

## 11. Критерии готовности продукта

- Команда Obsidian открывает вкладку агента в основной рабочей области, повторное выполнение приводит в уже открытую вкладку.
- Во вкладке отображается свежий отчёт целиком, включая общие новости, компании и график, а также ссылка на сохранённую заметку. Новые разделы можно добавить позднее.
- После настройки входных Markdown-файлов плагин создаёт заметку только в `Статистика` и возвращает во вкладку агента рабочую ссылку на неё.
- Повторный ручной запуск в тот же день добавляет раздел с новым временем. Интерактивный график IMOEX остаётся в последнем разделе, а старые вставки графика превращаются в ссылки, чтобы не было дубликатов.
- Если Obsidian работает, подготовка утренней сводки начинается за 30 минут до выбранного времени. В итог входят публикации за 24 часа до него по Москве; готовность может наступить позднее. После сна или запуска Obsidian позднее выбранного времени пропущенная утренняя сводка формируется один раз.
- Для ручного запуска и запуска после сна новости отбираются только за 24 часа до фактического начала запуска.
- Локальный режим проверяет доступность сервера и модели, не отправляет исходные тексты облачному LLM без отдельного согласия.
- Предзаполненные источники видны в настройках; пользователь может заменить отдельный источник на поддерживаемый, проверить подключение и вернуть значение по умолчанию. В отчёте указаны фактически использованные источники и единицы.
- Сводка содержит рыночный блок, ближайшие заседания, отобранные важные события с источниками и статус доступности источников. Отсутствующие данные названы отсутствующими; текст читается за 5–10 минут или быстрее при малом числе событий.
- Каждый блок компании в сводке содержит график, капитализацию выпуска и доступные новости. Вкладка агента показывает готовую сводку и ссылку на заметку.
- После формирования результата появляется локальное уведомление о готовности.

## 12. Решения, которые ещё нужно принять

1. Примеры четырёх Markdown-файлов приняты; перед реализацией парсера нужно проверить их на реальных пользовательских записях и, если потребуется, уточнить поддержку Markdown-экранирования и дополнительных столбцов.
2. Конкретные издания, адреса их лент и приоритеты, а также правила обработки платных и недоступных публикаций.
3. Перед возвратом раздела МСФО нужно определить проверяемые источники, перечень показателей, формулы вычисляемых величин и правила сопоставления компаний.
4. Настройки локального LLM-сервера и минимальные требования к качеству модели и времени обработки; поведение при временной недоступности сервера.
5. Вид уведомления при закрытой вкладке агента: уведомление Obsidian, системное уведомление или оба варианта.
6. Список альтернативных адаптеров для каждого типа данных и допустимые условия получения и использования их данных.
